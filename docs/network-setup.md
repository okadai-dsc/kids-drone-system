# ネットワーク設定メモ（IP・疎通確認）

各 Raspberry Pi と中央ノートPC をネットワークでつなぐときの考え方と手順のメモ。
「ポート開放が必要では？」「IP は誰が決めるの？」という疑問の整理を含む。

---

## 前提：想定しているアドレス

通信ポート・IP の正本は [../shared/ports.py](../shared/ports.py)。設計上の想定は次の通り。

| 機器 | 想定IP |
|---|---|
| 中央ノートPC（YOLO / モニタ / 結果表示を集約）| `192.168.0.100` |
| Raspberry Pi #1〜#4 | `192.168.0.11` 〜 `.14` |

> ⚠️ ただし ports.py の IP 値は「提案版（確認中）」。実ネットワークに合わせて **このファイル1箇所を直す**方針（後述）。

---

## 結論だけ先に

1. **ルーターの「ポート開放（ポートフォワーディング）」は不要。** 同じLAN内の機器同士は開放なしで通信できる。ポート開放はインターネット（外）から中へ入る通信のための設定。
2. **`192.168.0.x` と `192.168.11.x` は別サブネット（別の建物）。** IP の前半3つが違うと、部屋番号（末尾）を何にしても通信できない。全機で前半3つを揃えるのが大前提。
3. **IP を配るのは「DHCP（ルーターが自動）」か「静的（手動設定）」のどちらか。** スイッチ（ハブ）は IP を配らない（ケーブルを分岐するだけ）。DHCP がいないと OS が自分で `169.254.x.x`（リンクローカル）を名乗る。

---

## サブネットの考え方（マンションのたとえ）

| 用語 | たとえ |
|---|---|
| ルーター | マンションの建物＋管理人（部屋番号を配る）|
| スイッチ（ハブ）| 廊下の分岐。IP は配らない |
| 機器（Pi・PC）| 各部屋 |
| IP の前半3つ（`192.168.11`）| 建物の住所（＝サブネット）|
| IP の末尾（`.17`）| 部屋番号 |
| ポート番号（`11231` 等）| 部屋の中の受付窓口。アプリが使う番号でルーターに登録するものではない |
| ポート開放 | 建物の外（道路）から特定の部屋に直接入れるようにする設定。今回は不要 |

**同じ建物（同じサブネット）の部屋同士は自由に通信できる。** 別の建物（`192.168.0` と `192.168.11`）だと廊下がつながっていないので通信できない。

---

## IP は誰が決めるのか

| 方法 | だれが決める | いつ |
|---|---|---|
| DHCP（自動）| ルーター等の DHCP サーバー | 機器を接続すると自動で番号が付く |
| 静的（手動）| その機器自身に手で設定 | 自分で番号を決め打ち |
| リンクローカル（`169.254.x.x`）| OS が自分で名乗る | DHCP サーバーがいないとき（PC 直結など）の自動フォールバック |

`192.168.11.x` は `169.254` ではないので、**ルーターの DHCP が配った**か、**誰かが手動設定した**かのどちらか。スイッチや PC 直結だけでは出てこない番号。

## 実ネットワークとの食い違いへの対応

現地の実ネットワークが `192.168.11.x`（Pi が `.16` `.17` 等）だった場合、`192.168.0.x` 想定の ports.py と食い違う。合わせ方は2通り。

| 案 | やること | 手間 | 推奨 |
|---|---|---|---|
| **A: ports.py を実態に合わせる** | コードの `192.168.0` を実サブネットに書き換え。機器は今の建物のまま IP を固定 | コード1ファイル＋IP固定 | ◎ |
| B: ルーターの LAN を変える | ルーター管理画面で LAN 側 IP と DHCP 範囲を `192.168.0.x` に変更 | ルーター設定＋全機影響 | △ |

A を推奨（ルーターに触らない・他機器に影響しない・ports.py は元々1箇所で直す設計）。

## ⭐ Raspberry Pi 側で重要な設定

1. **サブネット（前半3つ）を全機で揃える** ← 最重要。ここがズレると末尾を何にしても通信不可。
2. **各 Pi に固定IP（静的IP）を設定する。** DHCP 任せの番号は再起動で変わりうるため決め打ちする。
   - 例: Pi#1〜#4 → `.11`〜`.14`、中央PC → `.100`
3. **OS バージョンで設定方法が違う（要確認）。**
   - 新しい OS（Bookworm / 2023-10 以降）→ NetworkManager（`nmcli`）
   - 古い OS → `/etc/dhcpcd.conf`
4. **静的IP設定で入れる値:** IPアドレス（例 `192.168.11.11/24`）、ゲートウェイ（ルーターの IP）。
5. **ファイアウォールで UDP を許可:** ビーコン `11231`、映像 `11111` など。中央PC は Avast が Tello 映像をブロックした実績があるので注意。

### Pi の現状確認コマンド

```bash
ip addr show                 # 自分のIP
ip route | grep default      # ゲートウェイ（ルーターのIP）＝DHCPを配った相手
cat /etc/dhcpcd.conf | grep -v '^#' | grep -v '^$'   # 手動設定(static)されているか
```

- `default via 192.168.11.1` などが出れば → ルーターがいて DHCP が配った
- `static ip_address=...` があれば → 手動設定済み
- `default` が出ないのに `192.168.11.x` なら → 手動設定のはず

### Pi 固定IP設定の参考リンク

- GUI での固定IP（やさしい）: <https://www.fabshop.jp/raspberry-pi-static-ip/>
- NetworkManager / nmcli（Bookworm 用）: <https://raspida.com/nmcli-static-ipaddress/>
- Bookworm の固定IP設定: <https://zenn.dev/technicarium/articles/9d3ee150a3cf04>

## 疎通確認の手順

### ① ping（IPレベル / L3）

中央PC から4台へ一括（zsh）:

```bash
for ip in 192.168.0.11 192.168.0.12 192.168.0.13 192.168.0.14; do
  ping -c 2 -W 1 $ip >/dev/null 2>&1 && echo "OK  $ip" || echo "NG  $ip"
done
```

> WSL2 から直接 ping すると Windows ホストのネットワーク／ファイアウォールを経由して実態と食い違うことがある。素の疎通確認は Windows 側 PowerShell か各実機から行うのが確実。

### ② 実際に使う UDP まで通るか（アプリレベル）

ping が通っても FW で UDP だけ落ちることがある。ビーコン（UDP `11231`）で確認:

```bash
# 中央PC（受信側）で待受
uv run python -m shared.tools.dump_beacon

# 各Pi（送信側）から中央PCへダミー送信
uv run python -m shared.tools.fake_beacon --host <中央PCのIP>
```

中央PC 側に `Tello#1 x=... batt=...` の行が 1Hz で出れば、ルーター経由で UDP が通っている。映像系（UDP `11112`〜`11115`）は [../shared/tools/check_tello_video.py](../shared/tools/check_tello_video.py) で確認できる。
